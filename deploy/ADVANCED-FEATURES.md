# Advanced functional requirements

Open **Advanced workflows** in staff navigation. Administrative pages are restricted to administrators. Managers and agents retain existing case-level permissions.

## Implemented locally

- **Progressed-case reconciliation:** preview counts, proposal/account selection, explicit same-person and invoice review, stale-review fingerprint, consistent pre-commit backup, atomic transfers, archived source, revoked private links/sessions, retained applicant-profile originals and source assessment/case snapshots. Numbered invoices and receipts remain distinct. Open hosted checkouts and duplicate placements block reconciliation. Both cases must have the same destination/pathway; nested merges require separate review. The retained current proposal must be active; a converted case retains a previously converted accepted proposal. Staff can access original profiles through the retained case.
- **Recurring, multi-step workflows:** ordered follow-up tasks, optional recurrence after completion, up to 20 steps and 10 escalating assignees per step, immutable execution snapshots, pause/resume, scheduler recovery and once-per-step protection. Escalation deadlines are UTC dates measured from the task's due date. The UI exposes three escalation levels; the API supports ten.
- **Document fields:** suggested identity/contact/passport/date fields, field validation, mismatch and expiry flags, staff editing/review, fingerprinted application of selected fields to current details. Source documents must be accepted/unexpired; signed originals are unchanged. Extraction is heuristic, not a claim of MRZ/identity verification accuracy. Scanner/OCR configuration remains as documented previously.
- **Reporting:** explicit stage probabilities, weighted ECC-payable quote totals separated by currency, excluded-case counts, saved-report scheduling to the creator's account email, current access checks at generation and idempotent outbox entries. Missing intervals generate one current report rather than a backlog of emails. No probability is invented by the application.
- **Commissions:** receipt-time staff/rate snapshots; cumulative-rounding refund adjustments; explicit policy approval; immutable adjustments, approval, idempotent payout recording and audit history. Historical receipts without trustworthy owner/rate history are marked for reconciliation, not assigned today's values. Payout recording does not transfer money. Supported policy is earning on receipt net of refunds; other commercial policies need specification.
- **Privacy:** approved general/financial/signed/backup periods, legal holds and releases, related-case checks, retention/outstanding-balance/provider-work blockers, backup before removal, stale-review checks and typed confirmation. Application personal data is removed/redacted; affected queued work is cancelled, incoming verified contacts are suppressed when no other active case needs them, and late callbacks cannot revive removed sessions. Requests remain `EXTERNAL_ERASURE_PENDING` until the backup window has expired and an administrator records evidence of backup/provider erasure. Shared accounts can retain information needed for other cases. Policies have no default approval.
- **Recruitment/admissions:** reviewed skills, education level, years of experience and language/test scores; explicit opportunity requirements; transparent pass/fail comparisons; supporting-document linking and review. Submitting/offering/accepting a placement requires configured supporting documents to have accepted, unexpired source records. Language/test score scales must match; education levels are ECC screening categories.
- **Localization:** approved language dictionaries, device language selection, RTL/LTR direction, public intake and portal support, per-case language preference, and automatic notification-template mapping. Static form labels/headings are available as translation keys; unmatched/dynamic phrases fall back to English. ECC must supply the target languages and approved translations. Notifications retain dynamic transaction/action content through the mandatory `{{body}}` placeholder; that content can remain in English until corresponding localized message generation is added. Legal/proposal snapshots are not rewritten.

## Integration functionality and actual remaining work

The application now has a **provider gateway integration hub**, not native Google, Microsoft, WhatsApp/SMS, accounting, or identity-provider adapters. It supports:

- Durable idempotency-keyed outbound jobs and HMAC-authenticated callbacks.
- Contact verification/consent, incoming message association, ambiguous-message quarantine, outgoing conversation records and revoked-consent checks.
- Outbound appointment updates/cancellation, inbound linked-event changes, conflict detection/resolution and booking overlap checks. Only CRM-linked appointments are synchronized. Calendar mappings currently have one provider event per task; simultaneous multiple-calendar mirroring needs further modeling.
- Invoice/receipt/refund synchronization jobs with stable application IDs and content snapshots.
- Hosted identity/signature session requests, client continuation links, evidence references, exact signed-proposal hash checks and staff review. A verified and staff-accepted provider signature can satisfy the signed-agreement conversion gate. No qualified-signature or jurisdiction-specific status is asserted.
- Unknown-delivery reconciliation rather than blind retry after timeouts/restarts.

**A real gateway implementing the selected providers, OAuth/account authorization, provider credentials and live acceptance are still required.** Setting a provider name does not implement or activate its native API. See [gateway contract](INTEGRATION-GATEWAY.md). Native provider adapters remain pending ECC's choices. No live message, account synchronization, identity check, signature request or payment was sent during implementation.

Integration delivery and local document processors use mocks.

Rendering tests cover each advanced page. Full interactive browser acceptance remains blocked by the local-listener restriction. Real provider behavior, OAuth, browser language switching and end-to-end mobile workflows need acceptance on a test deployment. The earlier dependency advisory review is still outstanding.
